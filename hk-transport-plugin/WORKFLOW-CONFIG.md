# 香港智能交通助手 — FastGPT 工作流配置指南

> 版本: 2026-05-06 | 适用于 hk-transport-plugin v0.1.0+

## 核心理念

```
用户自然语言 → LLM提取节点（意图理解+实体抽取） → 结构化参数 → 交通插件 → API结果
```

LLM 比正则表达式更擅长理解"下一班从落马洲由B1路往元朗方向的巴士什么时候到站"
这种复杂口语。因此工作流应配置 **LLM 提取节点**来做实体抽取。

---

## 推荐工作流架构

```
┌─────────────┐     ┌──────────────────────┐     ┌─────────────────┐
│  用户输入    │ ──→ │  LLM 提取节点         │ ──→ │  交通插件工具调用  │
│  (自然语言)  │     │  (意图+实体抽取)      │     │  (hk_transport)  │
└─────────────┘     └──────────────────────┘     └─────────────────┘
```

### LLM 提取节点 Prompt (推荐)

在 FastGPT 工作流中新增一个 LLM 节点，System Prompt 配置如下：

```
你是一个交通问题实体提取器。从用户的问题中提取以下信息，以 JSON 格式输出：

1. origin: 起点名称。如"落马洲口岸""尖沙咀""中环"
2. destination: 终点名称。如"铜锣湾""元朗""香港机场"
3. transportMode: 交通方式偏好，只能是以下之一：
   - "bus"（巴士）- 用户提到九巴/城巴/巴士/公交
   - "mtr"（港铁）- 用户提到港铁/地铁/东铁线/荃湾线等
   - "gmb"（小巴）- 用户提到小巴/专线小巴
   - "ferry"（渡轮）- 用户提到渡轮/天星小轮
   - "tram"（电车）- 用户提到电车/叮叮
   - 如果用户没指定，就不要输出这个字段

如果用户的问题中没有明确的起终点或交通方式，对应字段可以留空。

只输出 JSON，不要输出其他内容。

示例输入: "从落马洲站坐东铁线去尖东站，下一班车什么时候到？"
示例输出: {"origin":"落马洲","destination":"尖东","transportMode":"mtr"}

示例输入: "B1 巴士从新田开出的下一班实时发车时间"
示例输出: {"origin":"新田","transportMode":"bus"}

示例输入: "海港城到油麻地怎么走"
示例输出: {"origin":"海港城","destination":"油麻地"}
```

### 工具调用节点配置

将 LLM 提取节点的输出字段映射到交通插件参数：

| LLM 提取输出 | 插件 input key | 说明 |
|-------------|---------------|------|
| `origin` | `origin` | 起点 |
| `destination` | `destination` | 终点 |
| `transportMode` | `transportMode` | 交通方式 |
| （用户原始输入） | `question` | 兜底：当 origin/destination 为空时使用 |

---

## 兜底机制

如果 LLM 提取节点未能识别出起点/终点（origin/destination 为空），
插件会自动从 `question` 字段中解析（使用反向架构：全文扫描 9461 站点 + 正则兜底）。

---

## 最少配置（无 LLM 提取节点）

如果不想配置 LLM 提取节点，可以直接将用户输入传入 `question` 字段：

```
用户输入 → 交通插件 (question = 用户原始问题)
```

插件内部的反向架构会处理复杂的自然语言解析。但效果不如 LLM 提取节点好。

---

## 部署清单

1. 上传最新 `.pkg` 文件（`dist/hk_transport_assistant.pkg`）
2. **重启 plugin 容器**（关键！上传覆盖不会自动生效）
3. 在 FastGPT 管理后台 → 工作流 → 添加"工具调用"节点
4. 选择 `hk_transport_assistant` 工具
5. 配置参数映射（按上表）
