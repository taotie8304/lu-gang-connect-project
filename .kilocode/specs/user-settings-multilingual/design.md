# 设计文档：用户设置面板多语言支持和系统内容排版修复

## 概述

本设计文档描述了如何实现用户设置面板的完整多语言支持，以及如何修复隐私政策和个人资料收集声明的内容排版问题。

## 架构

### 多语言架构
- 使用 next-i18next 进行国际化支持
- 多语言配置文件位于 `packages/web/i18n/{locale}/` 目录
- 支持的语言：zh-CN（简体中文）、zh-Hant（繁体中文）、en（英文）

### 组件架构
- UserSettingsPanel：用户设置面板主组件
- SystemContentModal：系统内容显示弹窗
- 多语言配置文件：common.json, system_content.json

## 组件和接口

### 1. 多语言配置文件更新

#### 文件路径
- `packages/web/i18n/zh-CN/common.json`
- `packages/web/i18n/zh-Hant/common.json`
- `packages/web/i18n/en/common.json`

#### 新增翻译键
```json
{
  "user_settings": {
    "title": "设置",
    "activity_center": "活动中心",
    "account_info": "账户信息",
    "language": "语言",
    "change_password": "修改密码",
    "product_feedback": "产品反馈",
    "accessibility": "辅助使用设计",
    "logout": "登出"
  }
}
```

### 2. UserSettingsPanel 组件修改

#### 文件路径
`projects/app/src/components/UserSettingsPanel/index.tsx`

#### 修改内容
- 将所有硬编码的中文文本替换为 i18n 翻译键
- 使用 `t('common:user_settings.xxx')` 获取翻译文本
- 确保弹窗标题也使用翻译

## 数据模型

### 系统内容数据库文档
```typescript
interface SystemContent {
  key: string;           // 内容键，如 'privacy_policy'
  title: string;         // 标题
  content: string;       // Markdown 格式的内容
  createdAt: Date;
  updatedAt: Date;
}
```

## 正确性属性

*属性是关于系统行为的形式化陈述，应该在所有有效执行中保持为真。*

### 属性 1: 多语言文本一致性
*对于任何*支持的语言（zh-CN, zh-Hant, en），当用户选择该语言时，设置面板中的所有菜单项都应该显示该语言对应的文本，且不应该出现其他语言的文本。

**验证：需求 1.1, 1.2, 1.3**

### 属性 2: 系统内容标题格式正确性
*对于任何*系统内容类型（使用条款、隐私政策、个人资料收集声明），弹窗标题应该是人类可读的格式化文本，而不应该包含下划线或技术标识符。

**验证：需求 2.1, 2.2, 2.3, 2.4**

### 属性 3: Markdown 内容渲染完整性
*对于任何*系统内容文档，所有 Markdown 标记（标题、列表、段落）都应该被正确渲染，且章节序号应该连续且逻辑正确。

**验证：需求 3.4, 3.5, 4.4, 4.5**

### 属性 4: 语言切换响应性
*对于任何*用户，当切换语言设置后，设置面板和系统内容弹窗应该立即反映新的语言选择，无需刷新页面。

**验证：需求 1.1, 1.2, 1.3**

## 错误处理

### 多语言文本缺失
- 如果某个翻译键不存在，显示键名作为后备
- 记录警告日志，便于开发者发现问题

### 系统内容加载失败
- 显示友好的错误提示
- 提供重试机制
- 记录错误日志

### Markdown 渲染错误
- 使用安全的 Markdown 渲染器
- 对于无法渲染的内容，显示原始文本
- 记录渲染错误
