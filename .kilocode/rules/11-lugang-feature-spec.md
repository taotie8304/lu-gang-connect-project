# 鲁港通 - 功能规格文档规范（/specs）

## 目录结构
- 所有功能规格统一放在仓库根目录的 `specs/` 下。
- 每个功能一个子目录，目录名使用 kebab-case，例如：
  - `specs/subscription-system/`
  - `specs/hk-gov-api-sync/`

每个功能目录必须包含：
- `requirements.md`：需求说明
- `design.md`：技术设计
- `tasks.md`：任务拆分

## requirements.md 模板
- 结构：
  - `# 功能名称`
  - `## 简介`：用 3–5 句话描述该功能解决什么问题、服务什么用户。
  - `## 用户故事`：若干条 “作为…我想要…以便…”。
  - `## 需求列表`：用编号列出主要需求。
  - `## 接受标准（EARS）`：为每个需求写 2–5 条接受标准，使用 WHEN/IF… THEN… SHALL… 的句式。[web:23]

## design.md 模板
- 结构：
  - `## 总体设计`：整体流程说明，可以配简单序号步骤。
  - `## 影响范围`：
    - 前端文件列表（路径 + 简要说明）
    - 后端文件列表
    - 数据库表/集合及字段变更
  - `## 接口设计`：
    - 每个 API 的 URL、方法、请求/响应字段、错误码。
  - `## 边界情况`：异常场景、权限控制、超时等。

## tasks.md 模板
- 结构：
  - `## 开发任务`：用勾选框列出可以交给 Cursor 的任务，例如：
    - [ ] 创建订阅计划的数据模型
    - [ ] 实现前端订阅支付页面
    - [ ] 集成支付网关（例如 Stripe 或微信支付的伪接口）
  - 每个任务下可附带：
    - 涉及的文件列表
    - 验收方式（要跑哪些测试、如何在浏览器里验证）
